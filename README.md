# ВрвТура – организатор на планинарски тури

Динамичка веб-апликација од серверска и клиентска страна · **Веб програмирање 2026**

ВрвТура е апликација за планинарски клуб. Клубот објавува организирани тури, корисниците се пријавуваат на нив и оставаат коментари и оцени. Главната надградба е **временската прогноза за конкретниот врв и денот на турата**, преземена од надворешниот извор **Open-Meteo API**. Врз основа на прогнозата апликацијата проценува дали условите се поволни.

- **Објавена апликација:** `https://ВАШИОТ-ЛИНК` *(дополнете по објавувањето, види подолу)*
- **REST API документација:** `/api/docs/`
- **OpenAPI спецификација:** `/api/swagger.json`
- **Маски од Дел 1:** `/del1/`
- **Почетна состојба на базата:** `/db`

## Стартување локално во Docker

Потребно е само [Docker Desktop](https://www.docker.com/products/docker-desktop/).

1. Отпакувајте го проектот и отворете терминал во папката `vrvtura-app`.
2. Стартувајте ја апликацијата:
   ```bash
   docker-compose up --build
   ```
   Се креираат два контејнери:
   - `vrvtura-mongo`: виртуелизирана MongoDB база
   - `vrvtura-app`: Express сервер со изградената React апликација
3. Отворете http://localhost:3000/db и кликнете **„Внеси податоци“**.
4. Отворете http://localhost:3000. API документацијата е на http://localhost:3000/api/docs/.

За запирање притиснете `Ctrl+C` или извршете `docker-compose down`. Ако додадете `-v`, ќе се избрише и базата.

## Стартување без Docker (развој)

Потребни се Node.js 20+ и локална MongoDB.

```bash
cp .env.example .env              # прилагодете ги вредностите
npm install
npm run dev                       # сервер на http://localhost:3000
# во друг терминал:
cd app_public && npm install && npm run dev   # React на http://localhost:5173 (проксира /api)
```

За продукциска верзија извршете `npm run build` (ја гради React апликацијата во `app_public/dist`), а потоа `npm start`.

## Објавување во облак (продукција)

1. **MongoDB Atlas:** креирајте бесплатен кластер (M0) и корисник за базата. Во *Network Access* дозволете `0.0.0.0/0`, па копирајте го connection string-от.
2. **Хостинг:** користете Render, Railway или Heroku. Поврзете го GitHub складиштето.
   - Build команда: `npm install && npm run build`
   - Start команда: `npm start`. За Heroku веќе постојат `Procfile` и `heroku-postbuild`.
   - Променливи на околината:
     - `NODE_ENV=production`
     - `MONGODB_ATLAS_URI=<connection string>`
     - `JWT_SECRET=<долг случаен текст>`
     - опционално: `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`
3. По објавувањето отворете `https://<вашиот-домен>/db` и внесете ги иницијалните податоци. Потоа дополнете го линкот на врвот од овој README.

**Избор на база:** кога `NODE_ENV=production`, апликацијата автоматски ја користи `MONGODB_ATLAS_URI`. Во сите други случаи (локално, Docker) ја користи `MONGODB_URI`, односно локалната база. Ова е имплементирано во `app_api/models/db.js`.

**Е-пошта:** ако `SMTP_HOST` не е поставен, пораките не се праќаат, туку се печатат во конзолата на серверот (`[е-пошта] до ...`). Така може да се провери дека се генерираат. За вистинско праќање може да се користи на пр. Gmail со „App password“ или Mailtrap.

Контролата на пристап се прави на две нива:

- **Сервер:** `requireAuth` и `requireAdmin` во `app_api/middleware/auth.js`. JWT токенот се праќа во заглавјето `Authorization: Bearer ...`.

## Колекции во MongoDB (7, од кои 3 зависни)

| Колекција | Опис | Зависи од |
|---|---|---|
| `users` | корисници, хеширана лозинка, улога, лична листа за опрема | Equipment (листа) |
| `locations` | врвови: регион, височина, координати (за Open-Meteo) | – |
| `equipment` | каталог на опрема | – |
| `tours` | тури | **locations**, **users** (водич) |
| `registrations` | пријави на тури, статус, превоз | **users**, **tours** |
| `comments` | коментари, оцени, одговори | **users**, **tours** |
| `activities` | историски преглед на активностите | users, tours |

Бришењето тура ги брише и нејзините пријави и коментари. Врв со тури не може да се избрише (409).

## REST API (кратко)

Целосната документација со можност за тестирање е на `/api/docs/`. За заштитените методи прво повикајте `POST /api/auth/login`, па внесете го токенот преку копчето **Authorize**.

| Метод | Рута | Пристап |
|---|---|---|
| POST | `/api/auth/register`, `/api/auth/login` | сите |
| GET | `/api/tours` (q, difficulty, region, from, to, maxLength, available, period, sort, page) | сите |
| GET | `/api/tours/:id` | сите |
| POST / PUT / DELETE | `/api/tours`, `/api/tours/:id` | админ |
| GET | `/api/tours/:id/history` | админ |
| GET / POST | `/api/tours/:id/registrations` | админ / најавен |
| GET | `/api/registrations/me` | најавен |
| DELETE | `/api/registrations/:id` | сопственик или админ |
| GET / POST | `/api/tours/:id/comments` | сите / најавен |
| DELETE | `/api/comments/:id` | автор или админ |
| GET / POST / PUT / DELETE | `/api/locations`, `/api/equipment` | сите (GET) / админ |
| GET / PUT | `/api/users/me` | најавен |
| PUT | `/api/users/me/equipment` | најавен |
| GET / PUT / DELETE | `/api/users`, `/api/users/:id` | админ |
| GET | `/api/activities/me` | најавен |
| GET | `/api/activities` | админ |
| GET | `/api/stats` | сите |
| GET | `/api/stats/admin`, `/api/reports/tours.pdf` | админ |
| DELETE | `/api/db` | сите (за тестирање) |
| POST | `/api/db/seed` | сите (за тестирање) |

**Статуси:** `200`, `201`, `204`, `400` (невалидни податоци, со `errors` по поле), `401`, `403`, `404`, `409` (конфликт), `500`.

**Интегритет на податоците** се проверува на три нива:

1. **Клиент:** `app_public/src/utils/validators.js`
2. **Апликација:** `app_api/utils/validation.js`, пред податоците да стигнат до моделот
3. **Шема:** Mongoose `required`, `match`, `enum`, `min`/`max`

## Резиме на функционалностите

- **Неколку кориснички улоги** (гостин, корисник, администратор), со различни погледи и права.
- **Известувања по е-пошта:**
  - добредојде при регистрација
  - потврда на пријава или место на листа на чекање
  - ослободено место
  - нова тура (за претплатените корисници)
  - изменета тура
  - откажана тура со причина
- **Графикони** во админ таблата.
- **Напредни HTML компоненти:** `date`, `time`, `range`, `datalist`, switch, tabs, progress, modal.
- **Генерирање извештаи:** приказ за печатење и PDF со кирилица (pdfkit + DejaVu Sans).
- **Влечење и спуштање:** редослед на личната листа за опрема, кој се зачувува во базата.
- **Компонента за зумирање:** галерија со копчиња +/−, лизгач, тркалце и двоен клик.
- **Историски преглед на активностите:**
  - лична историја во профилот
  - историја на измени на тура (кој, кога, што се сменило)
  - сите активности во админ таблата
- **Интеракција помеѓу корисниците:** коментари, одговори (водичот е означен) и оцени со ѕвезди.
- **Листа на чекање:** кога ќе се откаже потврдена пријава, првиот што чека автоматски добива место и е-пошта.
- **Надворешен извор (Open-Meteo):**
  - прогноза за денот на турата
  - 7-дневна прогноза за секој врв
  - автоматска проценка (поволно / внимание / неповолно)
  - филтер „само со поволна прогноза“ во пребарувањето
